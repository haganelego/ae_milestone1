# Milestone-1: Convergence-Based Stop (Plan B-1) Evaluation

Generated by `scripts/16_convergence_eval.py` on 100-image dataset.

## Definition

### Deployable Convergence Stop (`convergence_stop`)

Uses ONLY past observations (levels <= t) to decide when to stop.
Suitable for real-time robot deployment.

- **Signal**: any per-level scalar (confidence, LLM saturation score, hybrid)
- **Rule**: Stop at first level t where:
  - t >= min_level (default 5)
  - t >= k+1 (so there are k real transitions)
  - Last k consecutive gaps are ALL < epsilon
- **Parameters**: epsilon=0.02, k=3, min_level=5

Key design: gaps are computed on REAL consecutive pairs only (level 2..N).
NO artificial zero is seeded at the start (the bug that was fixed).

### Oracle-Only Reference (`relative_to_max_stop`)

Peeks at the FULL series to find first level >= ratio * max(series).
NOT deployable; provided only for evaluation comparisons.

## Answers to Key Questions

### Q1: Does conf_convergence make ALL 100 images stop?

**Nearly: 99/100** images stop before max_level (vs baseline absolute: only 70/100).
This is a massive improvement over the absolute threshold approach which left 30% of
images never triggering. The 1 remaining image has confidence values that keep
fluctuating beyond epsilon=0.02 across the full 20 levels.

### Q2: Is conf_convergence closer to RelOracle than baseline?

**Yes.** conf_convergence MAE = 5.22 vs baseline_abs_conf04 MAE = 7.46.
That is a 30% reduction in error. The median AE is also better (4.0 vs 7.0).

### Q3: Does the gain-based bug fix change oracle_stop/relative_oracle_stop?

**Yes.** Before fix: oracle_stop.csv had 25/100 images with gain_stop=1
(impossible with real transitions since level 1 has no predecessor).
After fix: minimum gain_stop = 2 (correct), 0 images at level 1.
The threshold-based columns are unchanged (they don't use gains).

### Q4: Among convergence methods, which tracks RelOracle best?

**conf_convergence** is the clear winner among convergence-based methods:
- MAE = 5.22 (vs llm9b_convergence=5.63, hybrid=6.06, llm4b=6.07)
- Frac stop = 99% (vs llm9b=25%, hybrid=19%, llm4b=9%)

The LLM-based convergence methods mostly fail to trigger (they stay at max_level)
because the LLM saturation scores are highly variable (not smooth enough to
produce k=3 consecutive gaps < 0.02). This makes them poor candidates for
convergence-based stopping without parameter tuning.

## Interpretation

1. **conf_convergence is the recommended deployable stop** for the Milestone-1 PoC.
   It solves the absolute-threshold never-trigger problem (99% vs 70% coverage)
   and improves MAE by 30% over baseline.

2. The absolute hybrid (conf + LLM threshold) methods slightly beat pure
   conf_convergence on MAE (4.88 vs 5.22), but they require a carefully tuned
   absolute threshold and still depend on LLM inference at each level.

3. LLM saturation scores are too noisy for convergence-based stopping with
   epsilon=0.02, k=3. They would need either: (a) smoothing, (b) larger epsilon,
   or (c) smaller k. This is future work.

4. The bug fix is important: the artificial-zero seeding caused 25% of images
   to falsely saturate at level 1 in the gain-based oracle.
